# YouTube adapter decision — 2026-10-28

Keep gallery-dl 1.32.17 and the existing Instagram adapter. Add `instagram_local/youtube.py`, embedding yt-dlp through its Python API. Share the SQLite queue, worker restriction handling, output finalization, and offline Library. No generic downloader websites, browser automation, account rotation, PO-token provider, or challenge-bypass service is used.

Checked primary sources and the installed release:

- [Official yt-dlp documentation](https://github.com/yt-dlp/yt-dlp#readme): Python embedding, format selectors, native downloads, proxy, cookies, continued partial downloads, playlist limits, lazy enumeration, optional subtitles and thumbnails.
- [2026.10.26 release](https://github.com/yt-dlp/yt-dlp/releases/tag/2026.10.26) and [PyPI metadata](https://pypi.org/project/yt-dlp/2026.10.26/): updated the existing 2026.10.21 pin to the current stable release, requiring Python 3.11+. Instagram's real local DASH merge regression is rerun with this release.
- [Official JavaScript setup](https://github.com/yt-dlp/yt-dlp/wiki/EJS): explicitly enable the existing Node runtime (22+; tested 24.11.1). Install the exact `yt-dlp-ejs==0.8.0` dependency required by the pinned wheel. No runtime downloading of EJS components. Other default extras are not needed by the selected native streams or local FFmpeg conversion.
- [YouTube extractor and cookie instructions](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#youtube): public access is possible without account cookies, but account access and some formats are subject to YouTube's restrictions. Some formats require externally supplied tokens; this application does not obtain or bypass those. Challenges and access restrictions pause work.

The adapter deliberately selects native HTTPS / HTTP-DASH streams only. HLS formats can fall back to an external FFmpeg downloader with different proxy/TLS behavior, so they are excluded. Metadata, media, fragments, and explicitly requested sidecars share one yt-dlp client and explicit proxy configuration. `urllib.request.getproxies()` supplies environment/static Windows proxies when none is entered; PAC/WPAD is not executed. TLS verification remains enabled. FFmpeg runs locally for merging, stream-copy cuts, MP3 conversion, and previews.

Video selection chooses the largest known height within the ceiling, then frame rate/bitrate, among MP4 H.264/AV1 with AAC audio. Separate audio/video streams are merged without encoding video. Unsupported codecs, unknown heights, DRM, live streams, and cases without a suitable format fail explicitly. Audio-only chooses a usable audio stream and converts it locally to MP3. Segment MP4 cuts use nearby keyframes and can extend slightly beyond the requested times; this is disclosed before queuing and recorded in Library metadata. MP3 segments are cut during audio conversion. Full source download can be needed before local cutting.

### Original-audio correction

The previous bitrate-only audio selector ignored language preference and could choose a dub. The [official format-sort documentation](https://github.com/yt-dlp/yt-dlp#sorting-formats) prioritizes extractor language preference. The [pinned YouTube extractor source](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/yt_dlp/extractor/youtube/_video.py) identifies original audio with preference 10 and/or an original label, versus preference 5 for the default and negative values for other/descriptive tracks. The adapter now resolves original-track identity before protocol/codec/bitrate selection, preventing an unusable original from silently falling back to a dub. Non-DRC original variants are preferred when available. Missing multilingual identity produces an explicit failure; legacy single-language videos retain a clearly unverified fallback. No English preference is hardcoded.

Metadata-only checks of the reported video `Yctn_C_6cF8` confirmed ten languages. The old rule selected Indonesian Opus `251-8` for MP3 (157.832 kb/s), and French AAC `140-0` for MP4 (129.479 kb/s). The corrected selectors choose English (US) original Opus `251-9` (145.5 kb/s) and AAC `140-9` (129.476 kb/s), respectively. At a 360p ceiling the video selection is `134` plus `140-9`. No full download of this 1,107-second video was needed for diagnosis. Staging receipts bind resumable media to the audio-selection policy, format IDs and languages without persisting URLs. Library metadata now records selected language/original status; completed older files remain unchanged and can be explicitly downloaded again.

Playlists use flat lazy extraction, 50 entries per checkpoint batch, and retain the live iterator across batches. Restart or a connection/session change replays the extractor up to the persisted offset, preserving positions without storing undocumented YouTube continuation tokens. Limits are documented in README. Playlist membership commits atomically with queue discovery even if an existing file is skipped. No signed URLs, extraction dictionaries, cookie files, or account data are serialized into the database.

Local repeatable tests exercise the real yt-dlp/FFmpeg media pipeline using generated fixtures. A single public video (`jNQXAC9IVRw`, no cookies) was tested before and after tightening format selection. Both checks passed as a 240p MP4 under the 360p ceiling; the final native-HTTPS result was 629,172 bytes and decoded successfully by FFmpeg. Both temporary test directories were removed. An earlier attempt at the engine's historical test video returned unavailable. No playlist, high-volume, private-video, account challenge, or account stress test was run.
